1. **MEDIUM · Owner Actions → `Release Handoff Lock`, touching `Check Owner Replay` and `Respond Owner Replayed` · inside the range’s change; staged only**

   **A refused release can leave a marker that turns its retry into false success.**

   Scenario: request B validates handoff version V1. Another release and subsequent Main handoff replace it with V2 before B writes. B’s statement inserts its claim, but its version-checked UPDATE changes nothing and returns `state_changed`. This is a normal SQL result, so the claim commits despite the 502 response.

   Evidence: the changed SQL retains the claim when `upd` is empty. An offline probe executing the exported validation/replay nodes and actual dashboard mapper produced:

