The three classes

Same sentence, three machine truths

All three bubbles below carry the identical messageTemplates.handoff text — that is the trap this page defuses. What differs is everything the customer can't see: HTTP status, whether state was written, whether the owner is alerted. The class system — border style + glyph — makes the difference visible at a glance and carries into the build.

In flow

The lock, and the one-time reply

Once stage=handoff, every customer message routes to the lock: no LLM, no state write, no WhatsApp send. Decision K2 = C: the input stays open (a human will read what arrives), the lock reply is shown once, and later messages are accepted silently — the frontend suppresses the repeat, the engine is unchanged. No customer path unlocks it; only the owner does (the dashboard's single write action).

Engine-silent exits

SCREEN-INVENTORY §2.10 · §2.10.1 · W55–W60

Six exits where the engine hands the widget no customer text — each ruled on in §2.10.1. Two borrow existing config templates (W54 above, W55). One shows nothing at all (W56). Four are carrier/security-layer notices — the bot never ran, so they are deliberately not bot bubbles: a centered system strip, outside the bot's voice. Their four English texts live in §2.10.1 — the single source.
