# Rule: Cowork ↔ Claude Code governance sync

## Why
Two governance surfaces exist: the Cowork project instructions (not in git) and this repo
(`CLAUDE.md` + `.claude/rules/`). When a decision lives in only one of them they drift, and the build
stalls or repeats mistakes. This happened once (2026-07): Cowork gave instructions using rule files
and section anchors that belong to a DIFFERENT repository. The build stopped until it was untangled.

## The rules
1. **The repo is canonical for system rules.** Architecture invariants, security, contract integrity,
   Definition of Done and process gates live HERE. Cowork's instructions may NAME them but must not
   restate them — a second copy always drifts.
2. **Every standing decision made in chat lands in the repo** in the same or the next commit
   (`.claude/rules/` for a rule, `docs/ARCHITECTURE-DECISIONS.md` for a decision). A rule that exists
   only in a chat is a future contradiction.
3. **Stop-and-report on unknown paths.** If an instruction references a file or a section that does
   not exist in this repo: STOP, report it, propose a placement. Never guess, never silently create.
4. **`docs/REPO-MAP.md` is the shared map** of paths and `##` anchors (generated by
   `scripts/repo-map.sh`). Regenerate it whenever files or headings change; both sides consult it
   before giving or following path-level instructions.
5. **Declare deviations.** If the build departs from an approved plan, say so explicitly and record a
   line in the decision log — silent deviation is forbidden even when the new behaviour turns out to
   be better.
6. **An edit that invalidates existing text must CORRECT it, not sit beside it.** When a new rule or
   section supersedes an existing line, fix that line and state what changed and why. "Keep existing
   content" never means "leave a now-false line" — a silent contradiction inside one file is silent
   drift just like a cross-surface one.
