# /case-study

Turn a finished build into a portfolio/vitrin case study (the repo is the sales face).

1. **Problem** — what the shop loses without this (leads, interruptions).
2. **Approach** — the data flow in plain words (message → intent → route → book/lead/FAQ → reply).
3. **AI vs deterministic** — what the LLM does vs what IF/Switch does, and why (deterministic-before-AI).
4. **What was mocked** — config-driven services/prices/hours; test WhatsApp/widget. Mark mock as mock.
5. **What was learned** — the real lessons (e.g. no-double-book has no atomic lock → write-then-verify).
6. **One-swap-to-real** — exactly what changes to go live for a client.

Keep it honest (see [../rules/honesty-demos.md](../rules/honesty-demos.md)). No invented metrics.
